# Data Model: Auditoría funcional persistente

## AuditEvents

| Field | Type | Rules |
|---|---|---|
| `eventId` | text | Unique sortable identifier |
| `schemaVersion` | integer | Starts at `1` |
| `occurredAt` | date/time | UTC instant generated by Worker |
| `actorUserId` | text | `anonymous` when authentication did not establish identity |
| `actorDisplayName` | text | Safe display value |
| `operation` | select/text | Versioned operation name |
| `resourceType` / `resourceId` | text | Optional safe resource reference |
| `environment` | select | Optional `test` or `production` |
| `institutionId` / `applicationId` / `credentialId` | text | Optional known identifiers |
| `result` | select | `succeeded`, `failed`, `rejected` |
| `originIp` | text | Normalized client IP from trusted Worker metadata |
| `failureCode` | text | Safe controlled code, never raw exception/body |
| `requestId` / `operationId` | text | Correlation; operation optional |

## Prohibited content

Client Secret, password, token, OTP/code, delivery URL, full request/response body, Airtable PAT and raw stack trace. The event factory rejects unknown fields and applies redaction before persistence.

## Query model

Filters: `from`, `to`, `institutionId`, `applicationId`, `actorUserId`, `result`, plus `page`. Results sort by `(occurredAt desc, eventId desc)` and expose 20 items per page.

## Invariants

- One event is appended for every governed attempt, including authorization rejection.
- No API route mutates an existing event.
- An event remains meaningful if the referenced resource later disappears.
- Query authorization is checked before reading event data; the rejected query itself is appended with no leaked filters.
